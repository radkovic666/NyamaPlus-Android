# Optional Bulgarian OpenSubtitles picker — 1.0.43 / 45

Base: latest `origin/test` at `abe233a5393870c2bf0a045ce481b24f9780fd13` (1.0.41 / 43). Version skips the separate `nyamasubs` experiment's 1.0.42 / 44. No `nyamasubs` merge or changes to `main`.

Player 2 (`vaplayer.ru`) now **always** includes exactly one `ds_lang=bg`, in English and Bulgarian interfaces, on movies, series chooser, exact episodes, selection, fallback and renderer recovery. Player 1 embed URLs and existing provider behavior remain intact. Default playback navigates immediately; it neither checks nor waits for an OpenSubtitles backend.

TV: MENU, INFO, SETTINGS or CAPTIONS opens the native picker, above normal/HTML5 fullscreen. UP/DOWN and OK navigate/select; BACK closes the picker without arming playback exit. Outside it, OK/ENTER play-pause, LEFT/RIGHT ±10 seconds, UP/DOWN and two-step BACK retain their behavior. No TAB or virtual mouse. Mobile: use the existing Subtitles control; native dialog supports taps and does not alter rotation/touch/fullscreen rules.

First entry is always **Automatic Bulgarian (VidAPI)** / **Автоматични български (VidAPI)**, including when offline/unconfigured. It removes custom `sub_url`, `sub_file`, `sub_label`, `sub_lang`, `sub_default` and keeps `ds_lang=bg`. No reload when already automatic. Search starts only on explicit request. Results show actual Bulgarian release name, file ID, optional FPS/rating/downloads/format; none is synthesized. Generic series need a selected exact episode first.

Selecting an authorized result adds a directly fetchable signed HTTPS `sub_url`, `sub_lang=bg`, sanitized `sub_label`, `sub_default=true`, retaining Bulgarian fallback and other query options. At most one reload per confirmed selection. The app checks response media identity, file ID, offset, URL host/path/signature shape and short expiry. Only the server verifies the HMAC. Credentials are sent by native HTTPS to configured **nyama.fun** only, never to the provider/WebView or a redirected host. Existing activation storage/IDs/tokens are read without creating or mutating identity. No account password or OpenSubtitles secret enters the app.

Position is freshly probed only from one accessible finite-duration HTML5 video in the selected document/same-origin frames, or from the existing validated recent TV exact-episode bridge. There is no cross-origin injection, scraping, guessed movie clock or stream extraction. Known paused state sets `autoplay=0`. Unknown pause state also avoids forcing play. Without a verified position, selection/fallback asks before a potential restart and requests paused playback; old `resumeAt` is not misrepresented as a current position. Timing changes require a known position and otherwise leave playback unchanged.

After selecting a file, reopen the picker for timing −10…+10 seconds in 0.5-second steps, Reset and explicit Apply. Apply requests a shifted file from the backend's cached original; it is a deliberate reload, not live iframe synchronization. Choices remain scoped to this exact Activity/media session. Temporary signed URLs are not persisted to preferences or reused on another title/episode. Recovery strips expired file URLs and uses Bulgarian automatic configuration. API work runs on a worker, cancels/ignores stale responses on dismissal, pause, destroy, renderer loss or media change. No polling or startup requests. Automatic HTML5 policy does not override explicit external selection.

The checked-in build has an empty backend setting and **cannot return live OpenSubtitles results until deployment/configuration**. See [`server/opensubtitles/README.md`](../server/opensubtitles/README.md) for PHP, authorization adapter, credentials, exact download host allowlist, HTTPS routing, quotas and the public build property. The supplied adapter rejects every request until integrated with the deployed authoritative activation system. Nothing is automatically deployed or migrated.

Cross-origin provider limitations remain: `sub_default` behavior/rendering, internal subtitle load failures and exact movie position cannot be guaranteed or inspected. An exact signed-file HTTP/network/TLS failure reported by the active WebView triggers one fallback attempt, with restart confirmation if position is unknown. Other resources never trigger it. For an unobservable provider failure use the first automatic entry; the app does not claim automatic detection. A signed file may expire or be evicted before a later provider refetch. Bulgarian availability depends on the catalog; `ds_lang=bg` guarantees the configuration, not a subtitle file for every title. Constant offset does not repair a different cut or FPS drift. Real backend credentials, deployed authentication, provider playback and physical TV/mobile validation are outstanding.
