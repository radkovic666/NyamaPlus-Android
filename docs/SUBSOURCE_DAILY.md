Selecting a file requires the same existing movie or exact episode, authorized server selection, a short-lived same-host signed `.vtt` URL, then at most one deliberate reload with `sub_url`, `sub_lang=bg`, sanitized label and `sub_default=true`, retaining `ds_lang=bg`. Existing validated recent episode progress or reachable unambiguous HTML5 media supplies resume/paused state. Unknown position asks before restarting and requests paused playback; it does not invent time. Fallback removes all custom subtitle parameters, retaining exact identity and Bulgarian configuration, without contacting SubSource. No reload if already automatic. Exact observable signed-file failures may make one safe fallback attempt; unobservable iframe failures cannot be detected reliably. Menu dismissal, pause, destroy, media changes and renderer replacement invalidate stale requests/probes. Expired URLs are removed on recovery and are never persisted to preferences or copied between episodes.

TV uses fixed `https://nyama.fun/api/subtitles` on deliberate request. Server deployment/authorization/key/terms approval are still required; 401/403/429/schema/ZIP/unavailable states leave current playback intact. No key enters Android, Gradle, JS, playback URL or logs. Legacy mobile picker labels/protocol/build setting remain unchanged. The one public route can dispatch an existing mobile handler without introducing a second route/provider for TV.

No DNS, certificate, server or vhost replacement. The owner must inject `SUBSOURCE_API_KEY` privately on the existing PHP host and connect the adapter to deployed authoritative authorization. The adapter uses the supplied server helper contract and fails closed when unavailable; it is not represented as connected to production.

## Daily TV recommendations

Admission requires a valid IMDb ID, finite numeric **IMDb 6.5–10 inclusive**, the correct movie/series type and existing poster evidence. The owner confirmed catalog `items[].rating` is IMDb. No TVmaze/TMDb `vote_average` becomes IMDb; the old shared title-info alias was removed. Ordinary paged browse/search/filter results are not subject to this recommendation threshold.

“Selected today” and each recommendation genre row use the same gate. Picks are uniform shuffles **within the available eligible pool**, conditioned on preferring items not used in earlier rows and avoiding the prior day's row when enough alternatives exist. They are not ranked by score. A random per-day seed and selected IDs persist, keyed by device-local calendar date, section, backend identity and selection version 3. Existing nonempty rows remain stable if later pages arrive; newly available genres can appear without reshuffling those rows. Duplicate IDs within a row and identical title sets across rows are suppressed. Sparse pools may show fewer cards or omit redundant rows; nothing below 6.5 is invented to fill space. A date jump creates/reads the new day's state without crashing; jumping back beyond retained observation freshness can reduce the available pool.

Pool is capped at 240 recently observed/poster-validated catalog items. Cold/day-first selection can warm a **bounded background sample**, not a full catalog: at most three random additional 30-item pages (parallel, 8-second batch bound), and at most 24 eligible poster probes (existing six-worker pool, bounded checks). Already cached raw catalogs are reused. Attempts, including failures, are remembered once per local day/backend/section, preventing restart retry storms. First-page UI/search/filter controls remain responsive; recommendations show a preparing/empty state while the background pool completes. Without network, real eligible cached/observed entries remain; no fabricated ratings/posters. This is unbiased within the bounded candidate pool, **not a claim of uniform coverage of the entire remote catalog**. More observed pages improve future pools.

Unsupported/image caption formats and ambiguous multi-file archives are rejected, not claimed supported. A constant offset cannot repair a different cut/FPS drift.
